## Task 3 — Posologie Dialog: Auto-Generated Denomination

**Files:** `ViewModels/PosoListViewModel.cs`, `Views/PosoListView.xaml`

### ViewModel changes
- Removed `EditItemName` field (denomination is now computed, not typed)
- Added `AutoGeneratedName` computed property: `{qty} {posoform} x {prises} / {periode}`
- Added `partial void` property-changed handlers for `EditQty`, `EditPosoForm`, `EditPrises`, `EditPeriode` — each notifies `AutoGeneratedName`
- `SaveAsync()` now writes `AutoGeneratedName` → `itemname` instead of the free-text field
- Added `ShowSuccessAsync("Sauvegarde réussie", ...)` after every successful save

### Dialog layout changes
- Removed the "Nom *" free-text field
- Qté / Forme posologique / Prises now displayed in a single 3-column `Grid` row
- Période and Conditions fields follow below
- New blue card block showing the live **Dénomination (autogénérée)**
- New grey hint card showing the **Formulation (autogénérée)** formula description
- Nom formule and Substitut remain at the bottom (optional fields)

## Task 4 — Styled Material Design Message Boxes

**Files:** `Views/CustomMessageDialog.xaml`, `Views/CustomMessageDialog.xaml.cs`, `Services/DialogService.cs`, and 5 library ViewModels

### CustomMessageDialog (new)
Borderless, centered `Window` with:
- Colored top strip + PackIcon + title (blue = Info, green = Success, orange = Warning, red = Error)
- Message body text
- Primary button ("OK" or "Oui") + optional secondary "Non" button
- Static factory: `CustomMessageDialog.Show(title, message, type, hasCancel) → bool`

### DialogService.cs
All `MessageBox.Show(...)` calls replaced with `CustomMessageDialog.Show(...)`:

| Method | Dialog type |
|--------|-------------|
| `ShowInfoAsync` | Info (blue) |
| `ShowSuccessAsync` | Success (green) |
| `ShowWarningAsync` | Warning (orange) |
| `ShowErrorAsync` | Error (red) |
| `ShowConfirmAsync` | Info (blue) + Yes/No |

### Library ViewModels — added save success messages
`ShowSuccessAsync` added after every successful save in:
- `FamiliesListViewModel` — "Famille sauvegardée avec succès."
- `LabosListViewModel` — "Laboratoire sauvegardé avec succès."
- `FormesListViewModel` — "Forme sauvegardée avec succès."
- `VoiesListViewModel` — "Voie sauvegardée avec succès."
- `SpecialitesListViewModel` — "Spécialité sauvegardée avec succès."
- `PresentsListViewModel` — "Présentation sauvegardée avec succès."

Note: `DciListViewModel` already had a success message.

## Task 5 — Medic Denomination Auto-Rebuild on Inline Edit

**Files:** `Helpers/MedicDenominationHelper.cs` (new), `ViewModels/DenominationViewModel.cs`, `ViewModels/MedicListViewModel.cs`

### MedicDenominationHelper (new)
Shared static helper at `Helpers/MedicDenominationHelper.cs`.

Formula: `dose1 u1 dose2 u2 dose3 u3 dose4 u4 forme present colisage ucol`

### DenominationViewModel
Private `BuildDenomination` method now delegates to `MedicDenominationHelper.BuildDenomination` — no behavior change, logic is now shared.

### MedicListViewModel — SaveInlineEdit
Before calling `_repository.UpdateAsync(medic)`, the inline save now rebuilds the denomination:

```csharp
medic.itemname = MedicDenominationHelper.BuildDenomination(medic);
```

This means whenever a user changes `forme`, `present`, or any dose/unit field inline and the row is saved, `itemname` is automatically updated to reflect the current composition.
